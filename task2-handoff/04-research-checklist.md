# 第二道能力验证题｜正式开发前调研清单

> 本文件是新项目的调查任务清单，不包含任何 Creen.ai 现状结论。  
> 调研必须访问当时的真实网站并保留日期、URL、截图或 DOM/metadata 证据；不能依据模型记忆补全。

## 调研记录格式

每项观察至少记录：

- 调研日期、环境、登录状态、视口尺寸和地区（若相关）。
- 页面 URL、进入路径、截图/录屏或 HTML/metadata 证据。
- `Observed`（直接观察）、`Inferred`（合理推导）、`Unknown`（无法确认）的明确标签。
- 对产品范围、设计、架构、测试或验收的影响。
- 登录墙、付费墙或不可访问内容不得猜测；标记 `Requires access`。

## 技术方案候选

调研目标是形成带证据的候选比较，不是立即定案：

- 适合 SEO、Auth、Stripe 和异步 AI 任务的成熟 Web 工程底座。
- TypeScript 支持、路由/渲染方式、服务端能力、部署可移植性。
- 身份认证库/服务的第一方与 Google 支持、账号关联和测试能力。
- 数据持久化对用户、任务、计费账本、支付事件的一致性支持。
- AI 长任务、文件处理与结果交付所需的存储/任务机制；是否需要取决于模态调研。
- Stripe 官方 SDK、状态同步和本地/测试环境调试方式。
- 可观测性、错误追踪、审计与成本监控的最低必要方案。

输出应包含：候选、证据、优缺点、风险、成本、与 P0 的对应关系、推荐项和待确认项；推荐仍标为 `Candidate`，待范围/架构评审确认。

## 第三方真实 AI API 候选

对每个候选 Provider 调查：

- 是否覆盖已确认的模态、参数和质量需求。
- 是否提供正式 API、官方 SDK、异步任务、取消/重试和状态查询。
- 计价单位、最小计费粒度、失败是否收费、价格变更机制。
- 限流、并发、超时、区域可用性和服务条款。
- 输入/输出内容的存储、保留、训练使用和删除政策。
- 内容安全、版权、商用许可和水印要求。
- 测试额度、开发成本、密钥管理和可观测字段。
- 是否能提供真实调用证据并支持稳定的自动/人工验收。

最终输出只能是基于已确认模态的 shortlist。`AI Provider: TBD after API capability/cost/integration research.`
